Creating Custom Pipeline Steps

This guide explains how to extend the sigmapy library by creating your own custom pipeline steps and how to integrate them into a Sigma pipeline. Understanding this process allows for flexible and tailored data processing workflows.

Core Concepts​

Before diving into custom step creation, let's familiarize ourselves with the key components of the sigmapy pipeline framework:

  • Pipeline: The central orchestrator. It manages a sequence of processing steps, configuration, and data flow. You'll add your custom steps to a Pipeline instance.
  • PipelineConfig: A configuration object that holds settings for a pipeline run, such as the chosen catalog, sequencing type, tumor type, and various operational flags. Your custom steps can access this configuration.
  • Matrix: Represents the input mutation data (e.g., SNV spectra) for the pipeline. It's typically built from MAF files or CSVs and is accessible within your custom steps.
  • PipelineStep: The base class for all operations within a Pipeline. Each step in a pipeline, whether built-in or custom, is an instance of a class derived from PipelineStep. This is the class you will inherit from to create your custom logic.

Writing a Custom PipelineStep​

Creating a custom step involves defining a new Python class that inherits from sigmapy.base.PipelineStep. This class will encapsulate the specific logic you want to introduce into the pipeline.

Here's the basic structure:

from sigmapy.base import PipelineStep
import pandas as pd

class MyCustomStep(PipelineStep):
    def __init__(self, step="my_custom_processing", target="custom_output", catalog=None, description="This is my custom step.", pipeline=None):
        # It's good practice to call the parent constructor.
        # 'step', 'target', 'catalog', 'description', and 'pipeline' are common parameters.
        # The `pipeline` argument is crucial as it's passed by the `Pipeline.add_step()` method.
        super().__init__(step=step, target=target, catalog=catalog, description=description, pipeline=pipeline)
        
        # Add any other initialization specific to your step
        # For example, self.my_parameter = some_value

    def preprocess(self):

        Optional: Prepare data or configurations before the main execution.
        This method is called by the pipeline before `run()`.
        """
        super().preprocess() # If you want to include base class preprocessing

        # config = self.pipeline.config
        # signatures = self.pipeline.signatures
        #
        # print(f"Preprocessing {self.description}...")
        pass

    def run(self):
        """
        Core logic of your custom step.
        This is where your data processing, calculations, or transformations occur.
        The result should generally be stored in `self.output`.
        """
        print(f"Running {self.description}...")

        # input_data_df = self.pipeline.matrix.df
        # if self.pipeline.output is not None:
        #     previous_step_output_df = self.pipeline.output 
        
        # --- Your custom logic here ---
        # For instance, create a new DataFrame
        # Make sure your output is a pandas DataFrame if it's meant to be concatenated
        # with other pipeline step outputs.
        data = {'col1': [1, 2], 'col2': [3, 4]}
        self.output = pd.DataFrame(data)
        
        print(f"{self.description} finished processing.")

    def postprocess(self):
        """
        Optional: Clean up, finalize, or integrate the output after `run()`.
        This method is called by the pipeline after `run()`.
        Its primary role is to integrate `self.output` into `self.pipeline.output`.
        """
        # super().postprocess() # Call this if you want the base class's postprocessing logic.
                              # The base PipelineStep.postprocess handles concatenating self.output
                              # to self.pipeline.output.
        
        if not hasattr(self, 'output'):
            raise ValueError(f"Output is None. Please check the run method of {type(self).__name__}.")

        if self.pipeline.output is None:
            self.pipeline.output = self.output
        else:
            # Ensure column names are unique if concatenating side-by-side (axis=1)

            # Example:

            self.pipeline.output = pd.concat([self.pipeline.output, self.output], axis=1)
        
        # print(f"Postprocessing {self.description} complete.")

Key Methods Explained:​

  • __init__(self, step="default_step_name", target="default_target", catalog=None, description="Step description", pipeline=None, **kwargs):

    • The constructor for your step.
    • It's crucial to accept pipeline as an argument; the Pipeline.add_step() method will pass the pipeline instance here.
    • Call super().__init__(step=step, target=target, catalog=catalog, description=description, pipeline=pipeline) to initialize the base class attributes. The step parameter is a string identifier for your step, target can define what main entity this step focuses on (e.g., a specific signature), and catalog can specify if this step depends on a particular signature catalog.
    • You can add any other custom parameters your step might need (e.g., threshold=0.5). These can be passed when adding the step to the pipeline.

  • preprocess(self) (Optional):

    • This method is executed before the run() method.
    • Use it for any setup or preparatory work, like validating configurations or pre-filtering data.
    • You can access the main pipeline's data and configuration via self.pipeline (e.g., self.pipeline.matrix.df, self.pipeline.config, self.pipeline.signatures).
    • Calling super().preprocess() is good practice if you want to leverage any common preprocessing logic from PipelineStep or PipelineInbuildStep (if you were to inherit from that).

  • run(self) (Required):

    • This is where the primary computation or action of your step takes place.
    • Perform your analysis, data transformation, model prediction, etc.
    • The results of your step should typically be stored in an attribute named self.output. For compatibility with standard pipeline operations (especially if other steps will use your output or if it's part of the final pipeline result), self.output should usually be a pandas.DataFrame.

  • postprocess(self) (Optional but Recommended):

    • Executed after the run() method.
    • Its main responsibility is to integrate the self.output of your step into the collective self.pipeline.output.
    • The standard way to do this is: 
      if not hasattr(self, "output"):
          raise ValueError(f"Output is None. Please check the run method of the {type(self).__name__} class.")

      if self.pipeline.output is None:
          self.pipeline.output = self.output
      else:
          self.pipeline.output = pd.concat([self.pipeline.output, self.output], axis=1)
    • You can also use this method for any cleanup or final adjustments to your step's results. If you call super().postprocess(), the base PipelineStep class already provides the logic to concatenate self.output to self.pipeline.output.

Building a Sigma Pipeline with Custom Steps​

Once you have defined your custom PipelineStep class(es), you can integrate them into a sigmapy.Pipeline.

1. Initialize PipelineConfig and Matrix​

As with any Sigma pipeline, you'll first need your input data (Matrix) and pipeline configuration (PipelineConfig):

from sigmapy.core import PipelineConfig, Pipeline
from sigmapy.utils import Matrix
import pandas as pd
import os # For file paths in example

# Assume MyCustomStep is defined as in the previous section

# Example: Create a dummy matrix for demonstration
# In a real scenario, you would load this from a MAF file or CSV
data_dict = {
    'sample_id': ['sample1', 'sample2'],
    'mutation_type': ['C>T', 'C>A'],
    # ... (add other necessary columns for a valid matrix)
    # For simplicity, we'll assume a very basic structure.
    # A real matrix would have 96 mutation channels.
}
# Let's create a minimal valid-looking matrix structure for the example
# (actual matrix creation is more complex and context-dependent)
mutation_channels = [f'channel_{i}' for i in range(96)]
matrix_data = [[(i*j) % 100 for j in range(96)] for i in range(1,3)]
dummy_df = pd.DataFrame(matrix_data, columns=mutation_channels)
dummy_df['sample_id'] = ['sample1', 'sample2']
# In a real scenario, use:
# matrix = Matrix(input="path/to/your/matrix.csv or path/to/your/maf", ref_genome="path/to/ref_genome.fa")
# For this example, we'll mock it slightly:
matrix_obj = Matrix(input_df=dummy_df, sample_col='sample_id')


# Configure the pipeline
# Ensure you have a valid catalog file if your steps depend on it.
# For this example, we might not use a catalog extensively with a simple custom step.
# Replace with actual paths and configurations.
config = PipelineConfig(
    catalog="cosmic_v3_sbs", # Or any relevant catalog; ensure file exists
    seq_type="wgs",
    tumor_type="unknown", # Specify tumor type
    verbose=1 
)

2. Create Pipeline and Add Steps​

The recommended way to add custom steps is to initialize a Pipeline instance (potentially with default steps, or an empty list of steps) and then use the add_step() method.

# Initialize the pipeline. 
# To start with a clean slate (no default steps):
pipeline = Pipeline(config=config, matrix=matrix_obj, steps=[])

# Or, to include default steps and add yours afterwards:
# pipeline = Pipeline(config=config, matrix=matrix_obj) 

# Add your custom step(s)
# The `add_step` method instantiates your class and passes the `pipeline` instance to it.
# Arguments provided to `add_step` after the class name are passed to your custom step's `__init__`.
pipeline.add_step(MyCustomStep, 
                  step="my_first_custom_run", 
                  target="special_analysis", 
                  description="My first custom step instance")

# You can add multiple instances of the same custom step with different configurations
# pipeline.add_step(MyCustomStep, step="custom_step_variant2", my_parameter="another_value")


# You can also add built-in steps if needed
from sigmapy.base import DecomposeStep
pipeline.add_step(DecomposeStep, step="decomposition_after_custom", target="Signature_3")

The pipeline.add_step(StepClass, **kwargs) method does the following:

  1. Instantiates StepClass by calling StepClass(pipeline=self, **kwargs). This is why your __init__ must accept pipeline and any other arguments you pass through kwargs.
  2. Appends the created step instance to the pipeline's list of steps.

3. Run the Pipeline​

Finally, execute the pipeline as usual:

# Run the pipeline
pipeline_output_df = pipeline.run()

# Process or view your results
if pipeline_output_df is not None:
    print("\nFinal Pipeline Output:")
    print(pipeline_output_df.head())
else:
    print("Pipeline did not produce an output DataFrame.")

This pipeline_output_df will contain the concatenated results from all steps, including your custom ones, as managed by their postprocess methods.

Complete Example​

Let's put everything together with a simple, runnable example. This example will feature a custom step that adds a column based on some mock calculation.

import pandas as pd
from sigmapy.base import PipelineStep
from sigmapy.core import Pipeline, PipelineConfig
from sigmapy.utils import Matrix # For type hinting and conceptual understanding
import os

# --- 1. Define a Custom Pipeline Step ---
class AddDummyFeatureStep(PipelineStep):
    def __init__(self, step="add_dummy_feature", target="dummy_data", catalog=None, 
                 description="Adds a dummy feature column.", pipeline=None, new_column_name="dummy_feature"):
        super().__init__(step=step, target=target, catalog=catalog, description=description, pipeline=pipeline)
        self.new_column_name = new_column_name

    def run(self):
        print(f"Running: {self.description}")
        
        # Get the number of samples from the input matrix or previous output
        num_samples = 0
        if self.pipeline.output is not None:
            num_samples = len(self.pipeline.output)
        elif self.pipeline.matrix.df is not None:
            num_samples = len(self.pipeline.matrix.df)
        else:
            # Default if no prior data
            num_samples = 2 
            print("Warning: Could not determine number of samples from pipeline.matrix.df or pipeline.output. Defaulting to 2.")

        # Create a dummy feature - e.g., a series of numbers
        dummy_values = list(range(num_samples))
        
        self.output = pd.DataFrame({self.new_column_name: dummy_values})
        
        # If pipeline.matrix.df has an index you want to align with:
        if self.pipeline.matrix.df is not None and num_samples == len(self.pipeline.matrix.df):
             self.output.index = self.pipeline.matrix.df.index
        elif self.pipeline.output is not None and num_samples == len(self.pipeline.output):
             self.output.index = self.pipeline.output.index


    # We'll rely on the base PipelineStep.postprocess() to handle output concatenation,
    # so no need to override it unless custom logic is required.
    # def postprocess(self):
    #     super().postprocess()


# --- 2. Prepare Pipeline Configuration and Data ---

# For this example, we'll create a truly minimal DataFrame for the Matrix.
# In a real scenario, this would be your mutation count matrix.
example_matrix_df = pd.DataFrame({
    'sample_id': ['s1', 's2', 's3'],
    'colA': [10, 20, 30] # Simplified for brevity
})
# The Matrix class expects specific column structures (e.g., 96 mutation channels)
# For this example, we'll use 'input_df' and 'sample_col' which is a valid way to pass data,
# but a real sigmapy.Matrix would often be built from MAF/VCF or a full 96-channel CSV.
# To make it runnable without a full matrix, we'll assume 'sample_col' is enough for this demo's purpose
# when `Matrix` is initialized.
# Note: The `Matrix` class has validation. For a truly runnable example without external files
# or complex setup, we might need to mock `Matrix` or simplify its usage significantly.
# Let's assume `Matrix(input_df=..., sample_col=...)` is sufficiently functional for a custom step
# that primarily cares about sample count or basic DataFrame structure.

class MinimalMatrix: # A simplified mock for demonstration if Matrix class is too complex to instantiate simply
    def __init__(self, df, sample_col_name):
        self.df = df
        self.sample_col = sample_col_name
        # Add other attributes/methods if your custom step relies on them.
        if not self.df.index.equals(pd.RangeIndex(start=0, stop=len(df), step=1)):
             print("Warning: Matrix DataFrame index is not a simple RangeIndex. Ensure custom steps handle this if necessary.")


# matrix = MinimalMatrix(df=example_matrix_df.set_index('sample_id'), sample_col_name='sample_id')
# Using the actual Matrix class, but with a simplified input:
# The Matrix class will try to infer channel columns. If none of the typical 96 are found,
# it might behave unexpectedly or error depending on its internal validation.
# For a step that *only* adds a column based on sample count, this might be fine.
try:
    matrix = Matrix(input_df=example_matrix_df.set_index('sample_id'))
except Exception as e:
    print(f"Note: Instantiating sigmapy.Matrix with minimal data can be tricky due to its internal validations (error: {e}).")
    print("Using a simplified DataFrame directly for `pipeline.matrix.df` for this example's custom step.")
    # Fallback for the example if Matrix instantiation is too complex without proper data:
    class MockPipelineMatrix:
        def __init__(self, df):
            self.df = df
    matrix = MockPipelineMatrix(example_matrix_df.set_index('sample_id'))


# Create a dummy catalog file if your config points to one and it's checked
# For instance, if PipelineConfig checks for `catalog + ".csv"`
# Path to a dummy catalog file (e.g., in the same directory as the script)
dummy_catalog_name = "dummy_sbs"
dummy_catalog_file = f"{dummy_catalog_name}.csv"
if not os.path.exists(dummy_catalog_file):
    pd.DataFrame({'Signature': ['SBS1'], 'Type': ['Archaic']}).to_csv(dummy_catalog_file, index=False)


config = PipelineConfig(
    catalog=dummy_catalog_name, # Using dummy catalog
    seq_type="wgs",
    tumor_type="example_tumor",
    verbose=1
)

# --- 3. Create and Run the Pipeline ---
# Initialize pipeline with no default steps
pipeline = Pipeline(config=config, matrix=matrix, steps=[])

# Add the custom step
pipeline.add_step(AddDummyFeatureStep, new_column_name="my_custom_feature")

# Add another instance with a different column name
pipeline.add_step(AddDummyFeatureStep, new_column_name="another_custom_value", step="add_dummy_2")

# (Optional) Add a built-in step to see how it combines
# from sigmapy.base import DecomposeStep # Assuming this step can run with minimal data
# pipeline.add_step(DecomposeStep)

print("\nStarting pipeline...")
final_output = pipeline.run()

if final_output is not None:
    print("\n--- Final Pipeline Output ---")
    print(final_output.to_string()) # .to_string() to print all rows/cols for small df
else:
    print("\nPipeline did not produce an output.")

# Cleanup dummy catalog file
if os.path.exists(dummy_catalog_file):
    os.remove(dummy_catalog_file)

This example demonstrates:

  1. Defining AddDummyFeatureStep which inherits from PipelineStep.
  2. Its run method creates a new DataFrame with a single column.
  3. Initializing PipelineConfig and a simplified Matrix object (or a mock for robustness in the example).
  4. Creating a Pipeline instance, initially with no steps.
  5. Adding instances of AddDummyFeatureStep using pipeline.add_step(), showcasing how to pass custom arguments (like new_column_name).
  6. Running the pipeline and printing the output, which should include the columns added by the custom steps.

Remember to adapt the Matrix creation and PipelineConfig to your actual data and requirements when implementing your own steps. The example above simplifies these for clarity and to ensure it can run in a minimal environment.

Conclusion​

By following the structure outlined above—inheriting from PipelineStep, implementing the necessary methods (__init__, run, and optionally preprocess/postprocess), and integrating your step into a Pipeline object—you can effectively extend sigmapy to meet your specific analytical needs. This modular approach allows for complex workflows to be built from reusable and custom components.

Remember to thoroughly test your custom steps, especially their interaction with the Pipeline's data flow and other steps.
