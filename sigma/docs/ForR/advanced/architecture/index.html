SigMA System Architecture

This document describes the overall architecture of the SigMA project, including its directory structure, key components, and how they interact.

Repository Structure​

The SigMA repository is organized as follows:

  • R/: Contains the core R scripts that implement the SigMA logic. This includes functions for data processing, statistical calculations, machine learning model prediction, and plotting.
    • Key files: run.R (main workflow), decompose.R, calc_llh.R, predict_mva.R, etc.
  • examples/: Includes example R scripts demonstrating how to use SigMA for various analyses and data types. These are valuable for understanding common usage patterns.
  • inst/ ("installed files") Contains data files required by the package.
    • inst/extdata/: External data, including example datasets (examples/), GBM models (gbm_models/), signature matrices (matrices/), and repeat bed files (repeat_bed_files/). These are crucial for the functioning of SigMA, especially the pre-trained models and reference signatures.
  • man/: Contains R documentation files (Rd files) for the functions in the R/ directory. These are used to generate the package's help pages.
  • shiny/: Holds the R scripts for the Shiny web application (server.R, ui.R), providing a graphical user interface for SigMA.
    • shiny/www/: Web assets for the Shiny app (images, CSS, etc.).
  • docker-context/: Contains files to build a Docker image for SigMA (Dockerfile), facilitating deployment and reproducibility.
  • DESCRIPTION: Standard R package file providing metadata about SigMA (name, version, dependencies, etc.).
  • NAMESPACE: Standard R package file that defines exported functions and imported packages.
  • LICENSE: Contains the license information for the SigMA software.
  • README.md: Provides a general overview of the project, installation instructions, and links to further resources.
  • SigMA.Rproj: RStudio project file.
  • runShiny.R: A script to launch the Shiny web application.
  • manual_SigMA.pdf: A PDF manual which likely contains detailed usage instructions and potentially diagrams of workflows (contents not programmatically accessed).

Core Components and Workflow​

SigMA's workflow primarily revolves around the run.R script, which orchestrates a series of analytical steps:

  1. Input Data Processing:

    • SigMA typically takes a genome file (e.g., a CSV with SNV spectra) as input. This can be generated from VCF files using functions like make_matrix.R (inferred).
    • The input data is read and preprocessed, including filtering samples based on mutation counts.
    • It supports various data types/platforms (data parameter, e.g., "msk", "seqcap", "wgs") and tumor types (tumor_type parameter). Normalization based on trinucleotide frequency for the platform can be applied.

  2. Signature Analysis Core Calculations:

    • Likelihood Calculation: match_to_catalog.R (likely called by calc_llh.R or directly within run.R) calculates the likelihood of observed mutational spectra given reference signature catalogs (e.g., COSMIC signatures, tissue-specific average catalogs stored in sysdata.rda or inst/extdata/matrices). This involves functions like calc_llh.R.
    • Cosine Similarity: calc_cos.R (likely via match_to_catalog.R) computes cosine similarities between sample spectra and reference signatures.
    • Decomposition (Exposure Calculation): decompose.R (likely via match_to_catalog.R) uses methods like Non-Negative Least Squares (NNLS) to estimate the contribution (exposure) of different known signatures to each sample's mutational profile.

  3. Multivariate Analysis (MVA):

    • If do_mva = TRUE, SigMA uses pre-trained Gradient Boosting Models (GBMs) stored in inst/extdata/gbm_models/ to generate an MVA score. This is handled by predict_mva.R.
    • The MVA score helps in classifying samples, for example, for Homologous Recombination Deficiency (HRD) status, based on a combination of features derived from the previous steps.
    • The choice of GBM model depends on the data type and tumor_type.

  4. Assignment and Output:

    • Classification/Assignment: assignment.R uses cutoffs (potentially readjusted based on dataset characteristics if readjust = TRUE) on MVA scores or likelihoods to make binary classifications (e.g., "pass_mva", "pass_mva_strict").
    • MSI Status Check: If check_msi = TRUE, specific calculations are performed to identify microsatellite instability, which can confound certain signature analyses.
    • Output Generation: The results, including input spectra, calculated features, MVA scores, and classifications, are compiled into a data frame. This can be returned directly or saved to a CSV file. A "lite" format option is available (lite_df.R).

Key R Scripts and Their Roles (Summary)​

  • run.R: The main driver script. It initializes parameters, calls various processing and calculation functions, and manages the overall workflow.
  • match_to_catalog.R: A core function that performs matching of input genomes to signature catalogs using different methods (likelihood, cosine similarity, decomposition).
  • calc_llh.R: Calculates likelihoods.
  • calc_cos.R: Calculates cosine similarities.
  • decompose.R: Performs signature decomposition (e.g., NNLS).
  • predict_mva.R: Uses pre-trained GBM models to predict MVA scores.
  • assignment.R: Applies thresholds to scores/likelihoods for final classification.
  • make_matrix.R: Likely involved in creating the initial SNV spectra matrix from VCFs or similar formats.
  • list_options.R: Provides available options for parameters like data and tumor_type.
  • find_data_setting.R: Helps determine the optimal data setting if readjust = TRUE.
  • get_trinuc_norm.R: Provides trinucleotide context normalization factors.
  • plot_detailed.R, plot_summary.R, plot_tribase_dist.R: Generate various plots for visualizing results.
  • **utils.R: Contains utility functions used across the package.
  • Internal Data (sysdata.rda): This file (loaded automatically by R packages) contains essential internal data such as reference signature catalogs (catalogs, all_catalogs), GBM models (gbm_models), trinucleotide frequency weights (weight_3Nfreq), tissue names, platform names, etc., which are critical for SigMA's operations.

Data Flow​

  1. Input: User provides a mutation catalog (e.g., CSV file of 96-channel SNV counts per sample) via genome_file or an R data frame via input_df. Parameters like data, tumor_type, and catalog_name specify the context.
  2. Preprocessing: run.R filters samples and may normalize signature profiles based on trinucleotide frequencies (norm96 or internal weight_3Nfreq).
  3. Feature Calculation: run.R iteratively calls match_to_catalog.R (which in turn uses calc_llh.R, calc_cos.R, decompose.R) to compute likelihoods, cosine similarities, and signature exposures against specified catalogs (cosmic_catalog, average_catalog).
  4. MVA Prediction: If enabled, predict_mva.R takes these features and the input genomes to generate an MVA score using a pre-trained model.
  5. Assignment: assignment.R uses the MVA score or other metrics to assign a status (e.g., HRD positive/negative).
  6. Output: All calculated metrics and assignments are combined with the input data and returned as a data frame or written to a file.

Shiny Application (shiny/ directory)​

SigMA also provides a web-based graphical user interface built with Shiny.

  • ui.R: Defines the user interface elements (input fields, buttons, plot areas).
  • server.R: Contains the server-side logic that reacts to user inputs, calls the core SigMA functions (likely run.R or its sub-components), and generates outputs (tables, plots) to be displayed in the UI.
  • runShiny.R: Script to launch this application. The Shiny app essentially provides a user-friendly wrapper around the core command-line functionalities.

This architectural overview should provide a solid foundation for understanding how SigMA is structured and operates. For finer details, refer to the specific documentation for each core function.
