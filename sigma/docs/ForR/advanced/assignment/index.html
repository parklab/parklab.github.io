Core Function: assignment()

The R/assignment.R script contains the assignment() function. This function is responsible for assigning a binary status (e.g., positive/negative, pass/fail) for a specific mutational signature based on whether a calculated score exceeds predefined or custom thresholds. It translates quantitative scores into qualitative, actionable calls.

Purpose​

The primary purpose of the assignment() function is to apply decision thresholds to continuous scores—typically likelihoods from calc_llh() (via "median_catalog" method) or Multivariate Analysis (MVA) scores from predict_mva(). This converts these scores into categorical assignments (e.g., signature present/absent, HRD proficient/deficient), which are often the desired endpoint for interpretation.

Inputs​

The assignment() function takes the following parameters:

ParameterTypeDefaultTechnical Description & Implications
df_inDataFrameInput data frame. Crucially, this frame must contain the specific score column(s) that will be thresholded. For MVA, this is typically paste0(signame, '_mva') (e.g., "Signature_3_mva"). For likelihood ("median_catalog"), it expects columns matching grep(signame, colnames(df_in)) (e.g., "Signature_3_c1_ml", "Signature_3_ml").
methodString'mva'Specifies the type of score to use: 'mva' for MVA scores, or 'median_catalog' for likelihood-based scores. This dictates the logic for fetching cutoffs and identifying score columns.
signameString'Signature_3'The base name of the signature for which assignment is made (e.g., 'Signature_3', 'Signature_msi'). Used to construct the names of score columns in df_in and to fetch relevant cutoffs.
dataStringNULLDataset type/platform (e.g., 'msk', 'tcga_mc3'). Used with tumor_type to fetch appropriate pre-defined MVA cutoffs from sysdata.rda (cutoffs[[data]][[tumor_type]]) if not using custom cutoffs.
tumor_typeStringNULLTumor type. Used with data to fetch pre-defined MVA cutoffs.
weight_cfBooleanFALSEIf data = "msk" and method = "mva", and weight_cf = TRUE, specialized cutoffs (cutoffs_msk_cf, cutoffs_msk_strict_cf from sysdata.rda) are used. Indicates if cluster fractions were weighted during likelihood calculation, affecting MVA model choice for MSK data.
cut_varStringNULLIf using custom cutoffs (cutoffs_custom provided with non-standard limits), this string (e.g., 'fpr', 'fdr', 'sen') is used to name the output boolean columns (e.g., pass_mva_fpr_0.05). Reflects the metric used to derive the custom cutoffs.
limitsNumeric[]NULLIf using custom cutoffs, these are the specific limit values (e.g., 0.01, 0.05) corresponding to cut_var that were used to determine the cutoffs_custom. Used for naming output columns. If limits = c(0.1, 0.01) (default for FPR), standard column names pass_mva and pass_mva_strict are used.
cutoffs_customNumeric[]NULLA vector of custom cutoff values. If provided, these values are used directly for thresholding, overriding internal MVA cutoff mechanisms. The order should correspond to limits if custom naming is desired.
custom_modelBooleanFALSEIf TRUE and method = "mva", it attempts to load cutoffs (cutoffs_custom, cutoffs_strict_custom) from a custom GBM model file (path constructed using data parameter: inst/extdata/gbm_models/\${data}.rda). This allows using cutoffs bundled with a custom model.

Outputs​

The function returns a data frame (df_out) containing new boolean columns that indicate the assignment(s). The names and logic for these columns are as follows:

  • Likelihood-based (method = 'median_catalog'):

    • A column named pass_ml is created.
    • The logic: pass <- rowSums(df_in[, grep(signame, colnames(df_in))]) > 0.5 if multiple columns match grep(signame, ...) (e.g. Signature_3_c1_ml, Signature_3_c2_ml), otherwise pass <- df_in[, grep(signame, colnames(df_in))] > 0.5.
    • Rationale for 0.5 threshold: This is a common, though somewhat arbitrary, threshold for likelihoods or probabilities. If the sum of probabilities (or a single probability) attributed to the signature's components exceeds 0.5, it's considered "present".

  • MVA-based (method = 'mva'):

    • Default Cutoffs: If cutoffs_custom is NULL:
      • Cutoffs (cutoffs_this, cutoffs_strict_this) are fetched from internal data structures in sysdata.rda. The hierarchy is:
        1. If data == "msk" & weight_cf == TRUE: Uses cutoffs_msk_cf[[tumor_type]] and cutoffs_msk_strict_cf[[tumor_type]].
        2. Else if custom_model == TRUE: Loads \${data}.rda from inst/extdata/gbm_models/, expecting cutoffs_custom and cutoffs_strict_custom lists within, then uses cutoffs_custom[[tumor_type]] and cutoffs_strict_custom[[tumor_type]].
        3. Else if data is a key in cutoffs (standard models): Uses cutoffs[[data]][[tumor_type]] and cutoffs_strict[[data]][[tumor_type]].
        4. If no valid cutoffs found, an error occurs.
      • Generates columns:
        • pass_mva: TRUE if df_in[, paste0(signame, '_mva')] >= cutoffs_this. (Typically targets 0.1 False Positive Rate).
        • pass_mva_strict: TRUE if MVA score >= cutoffs_strict_this. (Typically targets 0.01 FPR).
    • Provided Custom Cutoffs (cutoffs_custom is not NULL):
      • If limits are c(0.1, 0.01) (or a permutation):
        • cutoffs_strict_this is set to cutoffs_custom[limits == 0.01].
        • cutoffs_this is set to cutoffs_custom[limits == 0.1].
        • Columns pass_mva and pass_mva_strict are generated as above.
      • Else (custom limits that are not the standard 0.1/0.01 pair, implies limits_custom = TRUE internally):
        • Iterates through each limit in limits and its corresponding cutoff in cutoffs_custom.
        • Score column is variable <- paste0(signame, '_mva'). (Note: code also refers to matching, which would be 'mva' here).
        • Output column name is constructed: paste0('pass_mva_', cut_var, '_', round(limits[[i]], digit = 2)). For example, if cut_var = "fpr" and a limit is 0.05, column is pass_mva_fpr_0.05.
        • Assignment: df_in[,variable] > cutoffs_custom[[i]]. (Note: code uses > not >= here).

  • The output data frame might also include a total_snvs column if it wasn't present in df_in. This is calculated as rowSums(df_out[, 1:96]), which could be problematic if df_out doesn't yet have the 96 channels (it should likely be df_in). This appears to be a minor potential issue in the original code logic if df_out is freshly created.

Algorithmic Detail​

  1. Initialization: Sets limits_custom = FALSE.
  2. Method Branching:
    • If method == 'median_catalog':
      • Sets matching = 'ml'.
      • Identifies score columns in df_in using grep(signame, colnames(df_in)).
      • If multiple columns match (e.g., Signature_3_c1_ml, Signature_3_c2_ml), their row-wise sum is compared against 0.5.
      • If a single column matches (e.g., Signature_msi_ml), its value is compared against 0.5.
      • Result stored in df_out$pass_ml.
    • If method == 'mva':
      • Checks if cutoffs are available for the data type or if custom_model = TRUE.
      • Cutoff Fetching (if cutoffs_custom is NULL):
        • Sets matching = 'mva'.
        • If data == "msk" & weight_cf == TRUE, uses cutoffs_msk_cf[[tumor_type]] and cutoffs_msk_strict_cf[[tumor_type]].
        • Else if custom_model == TRUE, loads \${data}.rda from inst/extdata/gbm_models/ and expects to find cutoffs_custom and cutoffs_strict_custom lists within that file, then accesses them by tumor_type.
        • Else if data is a recognized key in the global cutoffs object (from sysdata.rda), uses cutoffs[[data]][[tumor_type]] and cutoffs_strict[[data]][[tumor_type]].
        • If none of these conditions yield cutoffs, an error "invalid data selection" is raised (or "tumor_type not available").
      • Cutoff Application (if cutoffs_custom is NULL):
        • pass <- (df_in[, paste0(signame, '_mva')] >= cutoffs_this)
        • pass_strict <- (df_in[, paste0(signame, '_mva')] >= cutoffs_strict_this)
        • Stored in df_out$pass_mva and df_out$pass_mva_strict.
      • Using cutoffs_custom (if it's provided):
        • If limits matches c(0.01, 0.1) (order-insensitive):
          • cutoffs_strict_this is assigned the value from cutoffs_custom corresponding to the 0.01 limit.
          • cutoffs_this is assigned the value from cutoffs_custom corresponding to the 0.1 limit.
          • Assignments for pass_mva and pass_mva_strict proceed as above.
        • Else (non-standard limits):
          • Sets limits_custom = TRUE. (This triggers the loop below).
  3. Custom Limits Loop (if limits_custom = TRUE from MVA branch):
    • Determines the score variable: variable <- paste0(signame, '_mva').
    • Iterates i from 1 to length(limits).
    • For each i, a new boolean column is created/updated in df_out.
    • The column name is paste0('pass_mva_', cut_var, '_', round(limits[[i]], digit = 2)).
    • The assignment is df_in[,variable] > cutoffs_custom[[i]].

This function is thus a flexible rule-applier, translating continuous analytical outputs into discrete classifications based on a hierarchical system of cutoff determination.
