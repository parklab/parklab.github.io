Sigma Data Structures

This document outlines the key data structures used as inputs to and produced as outputs by SigMA. It also touches upon important internal R object structures that SigMA relies upon, primarily loaded from sysdata.rda.

Input Data Structures​

1. Mutational Spectra File/Data Frame​

The primary input for SigMA is a representation of mutational spectra for a cohort of samples. This can be provided to the run() function in two ways:

  • genome_file (CSV format):

    • A comma-separated values (CSV) file.
    • Structure:
      • Each row typically represents a single sample.
      • The first column often contains sample identifiers (e.g., "Tumor_Sample_Barcode", "SampleID").
      • The subsequent 96 columns represent the mutational counts for the 96 trinucleotide substitution types (e.g., ACG>A, ACG>C, ACG>G, ACG>T ... TTT>A, TTT>C, TTT>G, TTT>T). The order of these columns should be consistent and match the order expected by the reference signatures.
      • Additional columns might be present but are usually ignored by the core SigMA algorithms unless specifically named (e.g., a pre-existing total_snvs column).
    • Example: Files like examples/example_mmrd_SBS_matrix.csv. While MAF files (.maf) are mentioned (e.g., examples/tcga_mc3_brca.maf), these usually require preprocessing by a tool like make_matrix.R (or similar logic) to convert raw mutation calls into the 96-channel count matrix format before being used by run().

  • input_df (R DataFrame):

    • An R data.frame object.
    • Structure: Identical to the CSV format described above. The first column should be sample IDs, followed by 96 columns of mutation counts.

2. Reference Signature Catalogs​

While typically used internally from sysdata.rda, if one were to supply custom signatures to functions like calc_cos, calc_llh, or decompose, they would follow this structure:

  • R Matrix:
    • Each column represents a single mutational signature.
    • Each row represents one of the 96 trinucleotide mutation channels.
    • Values within the matrix are typically probabilities (each column sums to 1), representing the probability of each mutation type given the signature.
    • Column names are the signature identifiers (e.g., "Signature_1", "Signature_3", "SBS5").
    • Row names should correspond to the 96 mutation channels, matching the order in the input spectra.

3. Normalization Vector (norm96 parameter)​

  • R Numeric Vector:
    • A numeric vector of length 96.
    • Used for custom trinucleotide frequency normalization of reference signatures if built-in data platform normalizations are not suitable. Each element of the vector is a weight for the corresponding mutation channel.

Output Data Structures​

1. Main Output CSV / Data Frame from run()​

When run(return_df = FALSE) (default), a comprehensive CSV file is generated. If return_df = TRUE, an R data frame of the same structure is returned. This is the primary output containing all results.

  • Structure:
    • The initial columns are typically the input sample identifiers and the 96-channel mutation counts from the input spectra.
    • This is followed by a wide range of columns appended by the various analytical steps in run(). Key column groups include:
      • total_snvs: Total number of single nucleotide variants for each sample (sum of the 96 channels).
      • Likelihood-based scores (from "median_catalog" method via calc_llh):
        • Columns like Signature_3_c1_ml, Signature_3_c2_ml, ..., Signature_msi_ml, Signature_pole_ml. These represent the (normalized) likelihood or probability that a sample's spectrum matches specific reference signature clusters (e.g., different clusters representing Signature 3, or MSI-related average profiles). The exact names depend on the signame and tumor_type.
        • Signature_3_ml: Often a sum of the Signature_3_c*_ml columns.
      • Cosine Similarities (from "cosine_simil" method via calc_cos):
        • Columns like Signature_1_cs, Signature_3_cs, etc., for each signature in the selected cosmic_tissue catalog. Values are the cosine similarity scores.
        • max_cosine_simil_sig: Name of the signature with the highest cosine similarity.
        • max_cosine_simil_val: The value of the highest cosine similarity.
      • Decomposition Exposures (from "decompose" method via decompose.R):
        • Columns like exp_Signature_1, exp_Signature_3, etc., representing the estimated non-negative contribution (exposure) of each signature in the optimal decomposition.
        • error_nnls: The reconstruction error from the NNLS decomposition.
        • rat_sig3: Ratio of Signature 3 exposure to total SNVs (exp_sig3 / total_snvs).
      • MVA Scores (if do_mva = TRUE, from predict_mva):
        • Columns like Signature_3_mva or Signature_msi_mva, containing the score from the Gradient Boosting Model.
      • Assignments (if do_assign = TRUE, from assignment):
        • Boolean columns like pass_ml, pass_mva, pass_mva_strict.
        • If custom cutoffs were used with non-standard limits, names might be like pass_mva_fpr_0.05. These indicate whether a sample passed the threshold for a given signature based on a specific score type.
  • The exact set of columns can vary significantly based on the input parameters to run() (e.g., check_msi, do_mva, tumor_type, catalog_name).

2. Lite Output CSV / Data Frame (lite_df())​

If lite_format = TRUE in run(), the lite_df() function is called to produce a more summarized output.

  • Structure: This format typically retains:
    • Sample identifiers.
    • Key summary scores/assignments like Signature_3_ml, Signature_3_mva, pass_mva, pass_mva_strict.
    • It often omits the detailed per-signature cosine similarities, full decomposition exposures for all signatures, and individual likelihoods for all sub-clusters.
    • The goal is to provide a cleaner table with the most critical decision-support values. The exact columns are defined within the lite_df.R script.

Key Internal R Object Structures (from sysdata.rda)​

While users don't directly interact with these as input files, their structure dictates how SigMA processes data. These are extensively covered in the "System Architecture" document but summarized here for data structure context:

  • Signature Catalogs (catalogs, all_catalogs):
    • Lists of matrices. Each matrix has signatures as columns (probabilities, summing to 1) and 96 mutation types as rows.
  • GBM Models (gbm_models):
    • Nested lists (gbm_models[[data_type]][[tumor_type]]) containing gbm objects (from the gbm package). These store the trained Gradient Boosting Models.
  • Cutoff Lists (cutoffs, cutoffs_strict, etc.):
    • Nested lists providing numeric threshold values for MVA scores or likelihoods, used in the assignment() function. Structure often mirrors gbm_models access (e.g., cutoffs[[data_type]][[tumor_type]]).
  • Normalization Weights (weight_3Nfreq):
    • A list where each element is a named 96-element numeric vector, used for trinucleotide frequency normalization. Keys are data types.

Understanding these data structures is essential for preparing input for SigMA, interpreting its output files, and for advanced users who might wish to interact with its components or internal data more directly.
