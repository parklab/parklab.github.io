SigMA Options and Parameters

This section provides a comprehensive guide to the various options and parameters available in SigMA, primarily focusing on the main run() function. Understanding these is crucial for customizing SigMA's behavior for specific analyses.

The main function for running SigMA analyses is run(). Its parameters control input/output, dataset specifics, analytical choices, and more.

Parameters of the run() function​

The following are the primary parameters for the run() function, found in R/run.R:

ParameterTypeDefault ValueDescription
genome_fileStringNULLPath to a CSV file containing SNV (Single Nucleotide Variant) spectra information. Can be created from VCF using functions like make_genome_matrix(). One of genome_file or input_df must be provided.
output_fileStringNULLName for the output file. If NULL, the input file name is used, appended with "_output" and other run-specific identifiers.
dataString"msk"Specifies the type of sequencing platform or dataset. Affects model choice and normalization. Use list_data_options() to see available built-in options. Examples: "msk", "seqcap", "wgs", "tcga_mc3".
tumor_typeString"breast"Specifies the tumor type for the analysis. Affects model choice and reference signatures. Use list_tumor_types() to see available options and associated MVA models. Examples: "ovary", "bone_other", "breast".
catalog_nameStringNULLRequired. Name of the signature catalog to use (e.g., "COSMIC_v2", "COSMIC_v3"). The available catalogs are stored internally (likely in sysdata.rda as the catalogs object). The script will stop if not provided or if the name is invalid.
do_assignBooleanTRUEIf TRUE, a cutoff is applied to the MVA score (or other metrics) to convert them into binary classifications (e.g., pass_mva, pass_mva_strict).
do_mvaBooleanTRUEIf TRUE, multivariate analysis (MVA) using pre-trained GBM models is performed. Use has_model(data, tumor_type) to check MVA model availability for a given data/tumor_type combination. If no model exists for the selection, and custom = FALSE, the script may stop or warn.
check_msiBooleanFALSEIf TRUE, specific calculations are performed to identify microsatellite instable (MSI) tumors, which can confound HRD classification.
weight_cfBooleanFALSEDetermines if likelihood calculations should weight clusters by the number of tumors in each cluster (TRUE) or give equal weights (FALSE). Automatically set to TRUE for "seqcap" and "seqcap_probe" data, and FALSE for "wgs", "wgs_pancan", "tcga_mc3".
lite_formatBooleanFALSEIf TRUE, saves the output in a "lite" format, reducing the number of columns. See R/lite_df.R.
add_sig3BooleanFALSEIf TRUE, forces the calculation of Signature 3 likelihood, especially for tumor types where it wasn't discovered by NMF in their WGS data. Can be automatically set to TRUE under certain conditions if do_assign is TRUE.
norm96NumericNULLCustom normalization vector (96 values) for trinucleotide frequencies. Used to weight signatures if built-in data settings are not applicable or need overriding. If NULL, internal normalization factors based on the data parameter are used (from weight_3Nfreq in sysdata.rda).
customBooleanFALSEIndicates if a custom model or non-standard analysis is being run. This can affect model loading and cutoff application. If TRUE during MVA with readjustment, specific custom cutoffs (cut_var, limits, cutoffs_recalculated) might be used.
readjustBooleanFALSEIf TRUE, MVA score cutoffs are readjusted to match the median SNV counts in the current dataset. This involves potentially finding the best_model using R/find_data_setting.R and can trigger recalculation or simulation-based adjustment of cutoffs. Avoid for datasets with too few samples.
return_dfBooleanFALSEIf TRUE, the output is returned as an R data frame instead of being written to a file.
input_dfDataFrameNULLAn R data frame containing the input SNV spectra. Can be used as an alternative to genome_file.
snv_cutoffInteger5Minimum number of SNVs required for a sample to be included in MVA/assignment. Default varies by data and tumor_type if not explicitly set (e.g., 5 for some panels, 10 for exomes/WGS). This parameter sets a fixed cutoff if provided.

Discovering Options​

SigMA provides helper functions in R/list_options.R to discover available settings for some key parameters:

  • list_data_options():

    • Prints a list of available built-in data settings (sequencing platforms/dataset types) and their descriptions.
    • These options are typically keys in the internal platform_names object (likely in sysdata.rda).

  • list_tumor_types():

    • Prints a list of available tumor_type options and their descriptive names.
    • For each tumor type, it also lists the data settings for which pre-trained MVA models are available.
    • This information is derived from internal objects like tissue_names and gbm_models (likely in sysdata.rda).

  • has_model(data, tumor_type):

    • Returns TRUE if a pre-trained MVA model exists for the specified data and tumor_type combination, FALSE otherwise.
    • This is useful for programmatically checking if MVA analysis (do_mva = TRUE) is supported for a given configuration.

  • info_stat(data, tumor_type):

    • Prints information about Signature 3 fraction and median SNV counts for a given data and tumor_type, based on internal statistics (stat and snv_counts objects).

Internal Parameters and Variables​

Within the run() function and other core scripts, several internal variables and parameter sets control the execution flow. These are generally not set directly by the user but are derived from the main parameters or loaded from internal data stores (sysdata.rda):

  • catalogs: An R list object containing various signature catalogs (e.g., COSMIC versions). The catalog_name parameter selects one from this list.
  • all_catalogs: Another list, potentially more comprehensive or containing processed versions of catalogs for different tumor types or average profiles.
  • gbm_models: A nested list structure containing the pre-trained Gradient Boosting Models. Accessed via gbm_models[[data]][[tumor_type]].
  • signames_per_tissue_per_catalog: Defines which signatures are relevant or expected for a given tumor type and catalog.
  • platform_names: Maps data keys to descriptive platform names.
  • tissue_names: Maps tumor_type keys to descriptive tissue names.
  • weight_3Nfreq: Contains trinucleotide frequency normalization weights for different data platforms.
  • cluster_fractions: Used when weight_cf = TRUE to weight likelihood calculations by cluster occupancy.
  • Cutoff-related variables (used when readjust = TRUE or custom = TRUE): cut_var, limits, cutoffs_recalculated. These are typically determined internally by functions like adjust_cutoff or get_threshold.

Understanding these parameters allows for fine-tuned control over SigMA's execution and aids in interpreting its results and behavior under different conditions.
