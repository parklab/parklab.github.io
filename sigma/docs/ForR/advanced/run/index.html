Core Function: run()

The R/run.R script defines the primary orchestrating function run()^. This function serves as the main entry point for executing the SigMA analysis pipeline. It integrates various computational steps, from data input and preprocessing to signature analysis, multivariate prediction, and results output. Its behavior is heavily controlled by a rich set of parameters.

Purpose​

The run() function aims to provide a comprehensive analysis of mutational signatures in a given cohort of samples. It calculates likelihoods of observed mutational spectra against known signatures, computes cosine similarities, decomposes spectra into signature activities, and optionally performs a multivariate analysis (MVA) to predict certain characteristics (e.g., HRD status). Finally, it can assign samples to categories based on these results.

Inputs​

The run() function accepts numerous parameters, detailed extensively in the "Options and Parameters" section. Key parameters include:

  • genome_file / input_df: Input mutational spectra.
  • data, tumor_type, catalog_name: Define dataset context and reference signatures.
  • do_mva, do_assign, check_msi, readjust, custom: Control major analytical branches.
  • And many others fine-tuning specific steps.

(Refer to the "Sigma Options and Parameters" page for a complete list and descriptions.)

Outputs​

  • If return_df = TRUE, the function returns a single comprehensive R data.frame (merged_output) containing the input genomes merged with all calculated features, scores, and assignments.
  • If return_df = FALSE (default), it writes this data frame to a CSV file. The filename is automatically generated based on input parameters (input file name, tumor type, platform, etc.) or can be specified by output_file. A "lite" version of the output can be generated with lite_format = TRUE.
  • The function also prints messages to the console indicating its progress.

Algorithm and Key Logic Flow​

The run() function executes a complex sequence of operations:

1. Parameter Validation and Initialization​

  • Catalog Name Check: Ensures catalog_name is provided and exists in the internal catalogs list (loaded from sysdata.rda). If not, execution stops. The selected cosmic_catalog is loaded.
  • Cutoff Variables: Initializes cut_var, limits, cutoffs_recalculated to NULL. These are used if MVA cutoffs are readjusted.
  • Model & Data Settings for Readjustment: Initializes best_model and below_cutoff to NULL.

2. Initial readjust Logic (Finding Best Data Setting)​

  • If !check_msi & readjust is TRUE:
    • Calls find_data_setting(input_file, remove_msi_pole = F, tumor_type, input_df) to determine the optimal data setting based on the input data's characteristics.
    • If the best_model returned differs from the user-provided data, a warning is issued, and data is updated to best_model. This step aims to use the most appropriate pre-trained models.

3. weight_cf Adjustment​

  • Warns and forces weight_cf = TRUE if data is "seqcap" or "seqcap_probe" and do_mva = TRUE but weight_cf was FALSE.
  • Forces weight_cf = FALSE if data is "wgs", "wgs_pancan", or "tcga_mc3".
    • Rationale: Weighted cluster fractions (weight_cf=T) are deemed essential for certain panel data to account for differing representation of signatures in training, while for WGS/WES, equal weighting is preferred.

4. MVA Model Availability Check​

  • If do_mva = TRUE and not a custom model run:
    • Checks if a pre-trained GBM model exists for the current data and tumor_type combination within gbm_models[[data]] (from sysdata.rda).
    • If no model exists, execution stops with an error.

5. add_sig3 Logic​

  • If !add_sig3, do_assign = TRUE, "Signature_3" is relevant for the tumor_type and catalog_name, but no "Signature_3" components are found in all_catalogs[[tumor_type]], then add_sig3 is set to TRUE.
    • Rationale: Ensures Signature 3 calculations are performed if assignment related to it is expected, even if not explicitly requested for the tumor type's default catalog.

6. Input Data Loading​

  • Loads mutational spectra from input_df if provided, otherwise reads from genome_file (CSV). Stops if neither is available.
  • Removes samples with all NA spectra or zero total mutations. Samples below an SNV cutoff (if readjust=T) are stored in below_cutoff.

7. SNV Cutoff Application​

  • If do_assign = TRUE or do_mva = TRUE:
    • If snv_cutoff parameter is explicitly provided, samples with rowSums(genomes[,1:96]) < snv_cutoff are removed.
    • If snv_cutoff is NULL, a default cutoff is determined based on data and tumor_type (e.g., 5 for MSK/panels, 10 for WES/WGS, with some tumor-type specific exceptions). Samples below this are removed.
    • Rationale: Ensures that samples have sufficient mutations for reliable signature analysis, especially for MVA and assignment steps.

8. Informative Message​

  • Prints a message indicating the number of samples, tissue type (from tissue_names), and platform (from platform_names) being processed.

9. Main Processing Loop (Iterating through methods)​

This is the core analytical section. It iterates through a predefined sequence of methods to calculate various features.

  • Method Setup:
    • methods: Starts as c("median_catalog", "cosine_simil", "decompose").
    • sig_catalogs: Corresponding signature catalog types: c("average", "cosmic_tissue", "cosmic_tissue").
    • steps: Analysis context, initially c("mss", "mss", "mss") (Mismatch Repair Proficient).
    • signames: Target signature for each method, initially rep("Signature_3", 3).
  • Conditional Method Additions:
    • If tumor_type == "breast": Adds "weighted_catalog" method.
    • If do_mva = TRUE: Adds "mva" method.
    • If check_msi = TRUE: Adds "median_catalog" and "decompose" again, but with step = "msi" and signame = "Signature_msi".
  • Loop Execution: For each method in the methods list: a. Select Signatures:
    • Based on sig_catalog type ("average", "cosmic_tissue", "cosmic"):
      • "average": Uses all_catalogs[[tumor_type]] (or all_catalogs[['other_multisig']] if data == "op_multisig"). If add_sig3, Signature 3 from breast cancer is appended. For "msi" step, MSI and POLE signatures from all_catalogs are also added.
      • "cosmic_tissue": Uses cosmic_catalog subsetted by signatures relevant to the tumor_type (from signames_per_tissue_per_catalog[[catalog_name]][[tumor_type]]). For "msi" step or cosine similarity, additional MSI/POLE signatures are included. If add_sig3, Signature 3 from the base cosmic_catalog is appended.
      • "cosmic": Uses the full cosmic_catalog. b. Normalize Signatures (Trinucleotide Frequency Adjustment):
    • If data is not "wgs" or "wgs_pancan":
      • If norm96 (user-provided 96-value normalization vector) is available, signatures are multiplied by it.
      • Else, if data is in weight_3Nfreq (from sysdata.rda), signatures are multiplied by the corresponding platform-specific weights.
      • If data == "op_multisig", uses 'op' weights.
      • If no normalization available, stops with an error.
    • Signatures are then normalized to sum to 1 (column-wise: t(t(signatures)/colSums(signatures))).
      • Rationale: Adjusts reference signatures to the trinucleotide frequency context of the sequencing panel if it's not WGS. c. Ensure total_snvs Column: Adds genomes$total_snvs <- rowSums(genomes[, 1:96]) if not present. d. Perform Calculation:
    • If method != "mva":
      • Calls match_to_catalog(genomes, signatures, method, data, cluster_fractions_this).
      • cluster_fractions_this is derived from cluster_fractions (from sysdata.rda) if method == 'median_catalog' and weight_cf = TRUE. It provides weights for likelihood calculations based on cluster sizes in reference datasets.
      • If step == "msi", output column names are suffixed with "_msi".
    • If method == "mva":
      • Calls predict_mva(cbind(genomes, merged_output), signames[[imethod]], data, tumor_type, weight_cf, custom). merged_output contains results from previous methods. e. MVA Readjustment Logic (method == "mva" & readjust): This is a critical and complex section.
    • The goal is to adjust MVA score cutoffs if the current dataset's SNV distribution differs significantly from the MVA model's training data.
    • Prepare Data: Combines current genomes, merged_output, and current MVA output. If check_msi, removes highly probable MSI/POLE samples to create df_no_msi_pole.
    • Re-evaluate Best Data Setting: If best_model was not determined earlier (e.g., if check_msi=T), it calls find_data_setting() on df_no_msi_pole.
    • Recursive Call if best_model Changed: If the determined best_model differs from the current data:
      • A warning is issued.
      • The entire run() function is called recursively with data = best_model and readjust = TRUE. The result of this recursive call becomes the final result of the current call. This ensures the entire pipeline is re-run with the most appropriate settings.
    • Adjust Cutoffs (if best_model == data):
      • Attempts to get adjusted cutoffs using adjust_cutoff(df_no_msi_pole, data, tumor_type, below_cutoff). This function likely uses pre-calculated adjustments.
      • If adjust_cutoff returns valid cutoffs: custom is set to TRUE for the assignment step, and cut_var, limits, cutoffs_recalculated are set from adjusted_cutoff results.
      • If adjust_cutoff fails (returns NULL):
        • A warning is issued about suboptimal results.
        • Simulations are run: quick_simulation() generates simulated data (simul_df) based on df_no_msi_pole.
        • The run() function is called recursively on this simul_df (with do_mva=T, do_assign=T, check_msi=F) to get MVA scores for simulations.
        • Thresholds are derived from these simulation results using get_threshold() (e.g., for FPR 0.1 and 0.01 on Signature_3_mva). These become cutoffs_recalculated. f. Assignment Step (do_assign = TRUE and method is "median_catalog" or "mva"):
    • Calls assignment(output_comb, method, signames[[imethod]], data, tumor_type, weight_cf, custom_model = custom, cut_var, limits, cutoffs_custom = cutoffs_recalculated).
    • output_comb is cbind(genomes, output).
    • The custom, cut_var, limits, and cutoffs_recalculated (if set during readjustment) control how assignments are made.
    • The boolean assignment columns (e.g., pass_mva) are appended to output. g. Merge Results: Appends the output from the current method to merged_output. h. Post-hoc Calculations: Ensures rat_sig3 (ratio of Signature 3 exposure) and Signature_3_ml (sum of Signature 3 cluster likelihoods) columns are present if their components exist.

10. Final Output Generation​

  • The complete merged_output data frame is assembled.
  • If return_df = TRUE, merged_output is returned.
  • Else (write to file):
    • If readjust led to a change in data, the new best_model value is used for data.
    • An output_file name is constructed if not provided by the user, incorporating tumor_type, platform_name (derived from data and platform_names), and weight_cf.
    • If lite_format = TRUE:
      • Calls lite_df(merged_output) to get a reduced version.
      • Appends "_lite" to the filename.
      • Writes the lite data frame to CSV.
    • Else (full format):
      • Writes merged_output to CSV.
    • Prints a message with the output file path.
    • Returns the output file path.

Internal Data Dependencies​

The run() function heavily relies on internal data objects, typically loaded from sysdata.rda when the SigMA package is loaded. These include:

  • catalogs, all_catalogs: Collections of reference mutational signatures.
  • gbm_models: Pre-trained Gradient Boosting Models for MVA.
  • platform_names, tissue_names: Mappings for descriptive names.
  • weight_3Nfreq: Trinucleotide normalization weights.
  • cluster_fractions: Data for weighting likelihoods by cluster.
  • signames_per_tissue_per_catalog: Defines relevant signatures per tumor type/catalog.
  • cutoffs, cutoffs_strict (and variants like _msk_cf, _custom): Pre-defined MVA score thresholds for assignment.
  • stat, snv_counts (used by info_stat, potentially indirectly by find_data_setting or adjust_cutoff).

The run() function is a complex, central piece of SigMA, orchestrating numerous specialized functions and data resources to perform a comprehensive mutational signature analysis. Its parameter-driven conditional logic allows for flexible adaptation to various datasets and analytical goals.
